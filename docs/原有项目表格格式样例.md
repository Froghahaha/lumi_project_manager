# 表格信息提取样例（以 美尔斯-1 为例）
- 每个表格占用5行，对应表头从A-R列
- A列为项目名称，合并了A2-A6
- B列为项目正常/异常状态，合并了B2-B6
- C列为项目的equipments，合并了C2-C6，但是里面是多种设备混杂，不能直接提取到数据库，需要解析
- D3为销售人员名称
- D5为项目经理名称
- F2为立项日期
- F3为合同天数
- F6为收款进度（百分比）
- H2为机械设计执行人
- H5为调机执行人（重要！调机派遣不是调机执行人，验收执行人也是调机执行人）
- H5为验收执行人
- H6为尾款执行人
- I2为机械设计工序开始时间
- K2为机械设计工序计划的结束时间
- I3为生产工序开始时间
- K3为生产工序计划的结束时间
- I4为调机工序开始时间
- K4为调机工序计划的结束时间
- I5为验收工序开始时间
- K5为验收工序计划的结束时间
- I6为收款/尾款工序开始时间
- K6为收款/尾款工序计划的结束时间
- H3为生产执行人
- Q2~R2为机械设计工序的事件（也是多条混在一起，需要解析）+措施
- Q3~R3为生产工序的事件（也是多条混在一起，需要解析）+措施
- Q4~R4为调机工序的事件（也是多条混在一起，需要解析）+措施
- Q5~R5为调机工序的事件（也是多条混在一起，需要解析）+措施
- Q6~R6为尾款/收款工序的事件（也是多条混在一起，需要解析）+措施


# 特别的转换逻辑（以 美尔斯-1 为例）
- M2为机械设计的完结日期，如果为空，说明未完成，如果非空，说明已完成（已下发）
- M3为生产工序的完结日期，如果为空，说明未完成，如果非空，已完成生产（已下发）
- M5为调机工序的完结日期，如果为空，说明未完成，如果非空，已完成调机（已下发）
- P2~P6的状态值，是一个从属选项，工序状态不看这些值，而是以M列为准
- 存在有终端客户的项目名称，例如“宁波国帮-3 （金兔）”，则代表customer是宁波国帮，终端客户为金兔，意思是该项目为宁波国帮的第3个项目，终端客户为金兔
- 人员的角色和部门是直接对应的，知道角色就可以自动将其映射划归对应的部门了

# 例外情况（例如东睦新材料-7
项目有可能会有两个机械设计工序，
项目有可能会有两个生产工序
可能以上两个情况兼有
建议G列和H列结合起来，确定有多少个工序，以及对应的人员，然后推理其角色
